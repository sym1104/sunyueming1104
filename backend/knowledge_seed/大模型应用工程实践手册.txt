# 大模型应用工程实践手册

## 1. LLM 应用的典型四层架构

一个完整的大语言模型应用一般可以拆成四层：

第一层是表现层，也就是前端页面。它用原生 HTML、CSS、JavaScript 或 Vue/React 等框架实现，负责消息气泡展示、输入校验、流式打字效果、会话列表管理等交互。前端不应该直接保存大模型的 API Key。

第二层是中间层，通常由 Node.js + Express 或 Python + FastAPI 搭建。这一层承担 API Key 保管、跨域处理、统一响应格式、请求日志记录、提示词拼接、会话持久化等职责，是连接前端和模型服务的枢纽。

第三层是模型服务层。可以调用 SiliconFlow、阿里云百炼、七牛云、腾讯云 TokenHub 等平台提供的 chat/completions 接口，或者自己部署 Ollama / vLLM。这一层暴露的是标准的 OpenAI 兼容协议。

第四层是数据层，用 MySQL、PostgreSQL 等存储会话消息、知识库文档元数据、分块片段、用户信息等结构化数据；向量数据库（如 Qdrant、Milvus、pgvector）则负责存储文档的 Embedding 向量。

## 2. 提示词工程（Prompt Engineering）的核心要素

提示词的质量直接决定了模型输出的质量。一个好的提示词应该包括：

角色设定（Role）—— 告诉模型它是谁。例如"你是《高级网页设计》课程的助教"。
任务描述（Task）—— 明确要做什么。例如"请根据提供的知识片段回答用户问题"。
输入约束（Input）—— 说明输入数据的格式和范围。例如"用户输入是一段不超过 2000 字的中文问题"。
输出约束（Output）—— 规定输出的格式、长度、语气。例如"回答不超过 300 字，每个知识要点标注来源编号，找不到答案时明确说不知道"。
少样本示例（Few-shot）—— 给 2-4 组输入输出范例，引导模型模仿。
分步推理（Chain-of-Thought）—— 让模型先思考再回答，尤其是数学、逻辑、代码类问题。

## 3. 多轮对话的 Token 预算与历史压缩

大模型有上下文窗口限制（例如 8K、32K、128K tokens）。多轮对话不能无限累积，否则超过窗口就会报错。常见的解决方案有：

滑动窗口（Sliding Window）：只保留最近 N 轮对话，丢弃更早的。实现最简单，但早期关键信息可能丢失。

历史摘要（History Summarization）：在达到阈值前，用一次额外的 LLM 调用把早期对话压缩成一段简短的中文摘要，存到会话表的 history_summary 字段，下一轮请求时把摘要拼进 system prompt。

分层记忆（Hierarchical Memory）：分短期记忆（当前窗口）、中期记忆（摘要）、长期记忆（向量库）三层，按需要灵活调配。

实际项目中通常是滑动窗口 + 自动摘要的组合，4500 tokens 是一个比较常见的预算值。

## 4. 检索增强生成（RAG）的基本流程

RAG（Retrieval-Augmented Generation）是让模型回答私有领域知识的核心技术。完整流程：

第一步，文档入库。把 PDF、Word、TXT、PPT 等本地文件上传，用 officeparser / word-extractor / pdf-parse 等库解析成纯文本，再按 500 字左右的大小切分成带 overlap 的片段，每个片段算 token 数，存入 MySQL 或对象存储；同时对片段做 Embedding（向量化），存入 Qdrant / Milvus / pgvector。

第二步，检索。用户提问时，先对问题做 Embedding，到向量库里做余弦相似度 Top-K 检索；也可以结合 BM25 关键词打分混合排序，选出最相关的若干片段。

第三步，生成。把检索到的 Top-K 片段按格式拼进 system prompt，再加上用户的原始问题，一起发给大模型。模型看到知识片段后基于事实回答，显著降低幻觉率。

第四步，引用。在前端把回答中每个知识要点对应的片段来源标注出来，让用户知道答案是从哪个文件的哪一部分来的。

## 5. API Key 安全与服务端代理

前端代码是公开的，绝对不能把大模型的 API Key 硬编码在 JS 里或写进浏览器能看到的任何地方。正确做法：

后端创建 .env 文件存放 API Key、数据库密码等敏感配置，.env 加入 .gitignore 不进版本控制。前端只调自己后端的接口，后端再用 fetch 或 axios 转发到大模型服务。后端控制台打印完整的请求体和响应体，便于课堂演示时取证。

## 6. 大模型应用的实验要求

大连东软信息学院《LLM 应用设计》实验要求：掌握 chat/completions 接口调用；使用 Node.js + Express 搭建中间层；完成会话持久化与历史压缩；至少实现一个 RAG 或结构化输出功能；前端控制台打印请求和响应数据；后端终端打印发给大模型和从大模型接收到的完整 JSON；项目源码与接口数据库文档可完整复现。
